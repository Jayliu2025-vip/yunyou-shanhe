# v1.4.0 计划、设备与结果契约

## 实施范围

本版落实原方案的安全执行基础和可穿戴数据基础，保留v1.3.6美术。正式计划服务、医院上传、微信原生BLE桥接、具体手表SDK、医生复核工作台和正式力量处方尚未接入。不要把“接口存在”写成已经完成医疗系统联调。

## 计划

`PlanGateway({fetchPlan, verifyPlan})` 由可信宿主代码注入读取和验证实现。默认实例不请求网络，返回未接入。外部JSON字段 `signedBy` 或 `status` 本身不代表真实性。

网关先复制并冻结计划快照，再将该快照交给验证器，避免异步验证期间字段被改变；验证成功后仍需通过结构/时效检查。`canStartPlan` 同时检查网关来源和有效性，复制JSON不能保留内存中的来源凭据。此机制是前端正确性边界，不能替代服务端认证、授权、签名与审计。

| 字段 | 当前约束 |
|---|---|
| id / version / scope | 非空计划标识/版本；scope为demo或clinical |
| status / signedBy / signedAt | 正式计划必须active，具备验证过的签发信息 |
| rehabPhase / setting / mode | II或III；home或clinic；standing或seated，三者分开 |
| expiresAt / reviewDueAt | 正式计划未到期、未到复核日期 |
| warmupSec / mainSec / cooldownSec | 三阶段正数秒数；正式计划不能使用quick |
| warmupTempo / cooldownTempo / tempoMin / tempoStart / tempoMax / tempoDownStep | 由计划提供的节奏及可减载边界；低自评不会加速 |
| rpeScale / rpeTargetHigh / rpePauseAt / rpePromptIntervalSec | 当前支持project-0-10-v1；不将Borg 6–20自动换算 |
| requiredHr / allowHrFallback / sampleMaxAgeMs | 设备要求、明确降级许可及有效期 |
| hrZone / hrStopAbove / hrOverLimitSec | 目标区间与停止上限分开，演示不自动生成心率目标 |
| strengthBlocks | 正式版本当前必须false，避免用固定坐站演示替代力量处方 |

`createDemoPlan` 的节奏、提醒间隔、数据有效期等只用于软件体验与合成测试，不是临床推荐值。若真实计划包含当前不支持的量表/动作，拒绝执行并扩展适配器，不能猜测换算。

## 状态

`READY → ACTIVE ↔ PAUSED → COMPLETED/ENDED`；警示事件进入`SAFETY_STOPPED`，之后同一Game不可恢复或重新start。

暂停原因分别记录，关闭景点介绍不能清除后台、设备或疲劳暂停。恢复需检查当下症状、自评、说话情况、必要输入和计划有效性。设备恢复正常不会自动恢复训练。

正常结束保存结果后保留`POSTCHECK`，正向结束反馈保存且用户明确离开复核页后才finalize。停止或不适事件会保持阻断。任一步骤写失败时保留已有持久标记和本页内存阻断；刷新后的未确认标记也不自动清除。演示可以显式重置停止状态，但历史不适记录保留；正式模式没有患者自清除入口。

本地存储不是防篡改医疗审计系统，用户主动删除浏览器数据不能由H5阻止。生产环境需要服务端保存与复核状态。

## 设备

HRMonitor区分none、manual、ble、ws。有效读数要求当前连接代次、数值/单位、序列及新鲜度符合约束。BLE短包和明确接触丢失包不能保留旧值；无bpm或bpm为0的接触丢失消息也立即使旧样本失效。

WSS消息可包含 `bpm`（兼容hr/heart_rate）、`unit: bpm`、`sequence`、`contact`、`measuredAt`、`historical`。历史补传不视为实时数据；提供采样时间时，失效/明显偏离本机时间的包保守拒绝。未提供采样时间时只能验证到达新鲜度，无法据此证明设备实际采样时刻，需要在具体设备适配中验证。

接收后过期判断使用单调时间，避免系统时间倒退把旧样本变新。WebSocket消息长度受限，明文WS只允许本机调试，远端用WSS；真实网关身份认证仍需部署实现。

降级到手机模式必须经复核并由计划允许；降级时主动断开旧连接，迟到包无法复活旧源，HUD/采样/阈值读取也按当前监测模式限制。重新连接设备不代表已经完成临床准确性验证。

## 结果

`sessionSummary(session)` 输出schemaVersion、会话ID、计划ID/版本、数据分区、动作来源、阶段时长、自评量表、数值与固定事件摘要。`syncStatus` 当前为local-only。原始视频、姓名、任意metadata和原始设备消息不进入此契约。

主结果与旅程写入同一v2分区对象；按sessionId防重复，旧版数据不并入。v2 demo和clinical各有独立记录及停止标记。未来上传需基于会话ID实现幂等、认证、响应确认和失败重试，不能只依赖微信web-view的postMessage，也不能把console.log当作上传成功。

## 临床与平台边界

原则核对参考：AHA个人活动计划与警示症状、AHA/AACVPR 2024核心组成；链接见原循证方案。未把2026 ESC的表格、公式或推荐级别编入新自动处方逻辑。具体阈值、量表授权、运动动作、停止与复核规则需要临床团队审定。
