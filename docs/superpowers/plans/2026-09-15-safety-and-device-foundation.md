# 安全流程与设备基础 Implementation Plan

用户贴回循证设计并要求继续优化，按已明确的路线A实施。版本目标v1.4.0，保留v1.3.6美术。

## 范围

1. 可玩演示与正式康复入口分开；临床计划无可信提供方时阻止正式开训。只实现版本化计划校验与提供方接口，不伪造医生签发或自动读取医院服务。
2. 独立会话状态、不可恢复的症状停止、普通暂停复核、后台暂停、自评与症状分离、取消自动加速。
3. 演示/正式/旧版记录分区；开始前持久化活动标记；停止状态与存储失败明确处理；结果回传契约不包含原始视频。
4. 心率连接代次、样本有效期、乱序/异常输入检查、数据失效暂停；按计划要求决定是否可以降级。
5. 去除患者端绝对安全承诺及指南背书，保留文献在研究文档；提供合成验证与接入说明。

## 文件职责

- `js/session-safety.js`：唯一安全状态转换。
- `js/rehab-plan.js`：计划校验、明确标注的演示计划、可信提供方边界。
- `js/hr.js`：设备生命周期与实时样本质量。
- `js/storage.js`：分区、停止锁定、记录写入结果及最小回传结构。
- `js/game.js`：接入安全状态和输入守卫，绘制代码保持现有结构。
- `js/main.js` / `index.html` / `css/theme.css`：入口、前检、恢复检查、急停和持久化反馈。

## 顺序与验收

- [x] 先写回归测试，确认自动加速、可恢复不适、数据混存等现状失败。
- [x] 完成安全状态和计划契约的独立测试与实现。
- [x] 完成设备有效期/乱序/迟到回调及分区存储测试与实现。
- [x] 接入前端全部恢复入口、演示标识和异常处理。
- [x] 执行合成浏览器流程：无计划阻断、前检不适阻断、演示开训、暂停复核、症状停止、刷新仍锁定、演示重置与数据分区。
- [x] 检查视觉、控制可达性、语法、缓存、数据协议和文案；明确真机/医院联调尚未完成。

工程测试阈值只是合成演示参数，不能作为通用临床处方。本轮不存在真实医院验证服务，因此正式训练入口保持有据可查的未就绪状态。
