# 云游山河：循证优化与小喜鹊接入方案 v1

日期：2026-09-15。状态：供审阅的设计草案，尚未实施。

## 1. 本轮结论与范围

建议保留“原地踏步、抬手集章、云游山河”的玩法，将其完善为执行个体化康复计划的手机训练模块。先完善计划边界和安全停止，再统一患者界面，并建立可穿戴设备与小喜鹊的接入契约。

用户已确认：目前以手机独立使用为主，同时考虑后续接入可穿戴设备。手机独立使用指不强制额外心率设备；保留已有手机摄像头体感能力。手机、摄像头或普通手环本身不能确认患者适合运动。

对象以经康复团队评估的冠心病Ⅱ、Ⅲ期患者为核心。康复阶段与交付场景分开记录，不能把Ⅱ期固定等同于院内、Ⅲ期固定等同于任意居家训练。其他心脏病人群需要对应的临床计划，不能自动沿用冠心病参数。

### 三条实现路线

| 路线 | 内容 | 取舍 |
|---|---|---|
| A：在现有 H5 上完善安全、手机体验和接入契约（推荐） | 保留真实姿态识别和游戏资产；逐步拆分计划、设备、安全与报告模块 | 改动可分批验证；微信内摄像头和设备能力仍需真机确认 |
| B：立即迁移为小喜鹊 uni-app 原生页面 | 合并导航、原生摄像头和蓝牙入口 | 需要迁移 Canvas、音频与姿态运行时；工作量较大，不能由页面能编译推断识别可用 |
| C：仅统一配色和版式 | 快速改善观感 | 现有自动加速、停止后恢复、计划缺失等问题仍存在，不适合作为本次完整优化 |

第一轮按 A 设计。医学参数应来自康复团队审定的计划，不把指南中的人群建议直接变成所有患者的默认处方。此次软件验收使用合成数据；临床效果和设备测量准确性另行验证。

## 5. 第一轮患者流程

### 5.1 首页

“云游山河”名称和十三景保留。首屏显示今日计划卡、当前景点、已获得的印章和一个主要按钮。计划卡显示来源、有效性、今日阶段与允许的活动；没有计划时明确显示“尚未关联康复计划”，保留独立演示入口。

不要默认填入医院、医生或患者身份。演示页始终显示“演示”，用合成计划；患者自勾“医生已同意”不能在数据层变成真实医生签发。

### 5.2 出发准备

1. 查看计划：时长、姿势、活动、休息安排和监测要求只读；患者可选择计划允许的景点和表现形式。
2. 今日状态：逐项回答当前是否有警示症状、近期是否有被要求暂停运动的变化；不能用一个勾选代替风险评估。命中需要复核的条件则阻断，给出联系团队路径。
3. 手机摆放：保留真实姿态识别，提示稳定放置、清除障碍、全身或计划要求部位入镜；有稳定的识别反馈才进入体感模式。
4. 设备：默认折叠为“可选设备”。显示未连接、连接中、可用、数据过期、连接中断，并区分测量时间与接收时间。
5. 声音与操作说明：试听提醒音，展示暂停和“不舒服，停止”按钮。语音不可用时，说明视觉提示能力；如果该训练模式必须依赖语音，则阻断。

摄像头不可用时，不得悄悄改为自动行走并记录成患者训练。第一轮提供演示或返回；后续如设计无摄像头跟练，需要作为单独能力和记录来源。

### 5.3 训练

保留热身、主运动、整理三个阶段，其时长由计划给出。计划允许分段时支持短运动段与休息段，不把15/20/30分钟作为所有人的唯一选择。

界面只突出阶段、剩余时间、动作提示和当前自评状态；心率仅在有可用来源时出现，无设备显示“未监测心率”，不显示绿色的“安全”判断。

疲劳自评与症状按钮分离。既有0–10自评可暂保留为明确标注的项目自评，不能宣称与Borg 6–20固定等价。数据必须包含量表名称、版本、范围；正式量表及中文锚点需临床复核和必要授权。小喜鹊当前也使用0–10字段，但字段同名不代表两者定义已经一致。

自评提醒覆盖需要的训练阶段；过期未答时暂停等待，不能自动替患者选择“正常”。普通暂停不丢失已得印章。警示症状发生后立即冻结训练、计数和奖励，优先展示停止与求助说明；不要求先做整理或深呼吸才能退出。

### 5.4 结束

正常结束记录各阶段时长、活动和自评；主动结束与症状停止分别记录。报告显示“本次完成/提前结束/因不适停止”，不自动评定心肺功能改善。

停止后仍提供症状说明和联系路径。胸痛持续、严重气短、晕厥或其他疑似急症提示及时拨打120；软件不诊断原因，不承诺已经通知医生。安全停止不得因刷新、返回首页或重新进入而自动变为可继续。

## 6. 安全状态与计划边界

| 状态 | 允许行为 | 恢复规则 |
|---|---|---|
| READY | 核对计划与今日状态 | 全部前置条件满足后开训 |
| ACTIVE | 按计划训练、记录、集章 | 只允许计划内操作 |
| PAUSED | 普通休息、提醒未答、页面隐藏、必要输入失效 | 补齐检查后用户手动恢复 |
| SAFETY_STOPPED | 警示症状或计划要求终止的事件 | 本次会话不可恢复；保留原因，进入医疗复核路径 |
| COMPLETED / ENDED | 保存结果和回传 | 不再接收运动计数或迟到回调 |

安全状态从游戏绘制中分离，提供唯一转换入口。弹窗、音频回调、设备更新和场景切换都不能越过它。SAFETY_STOPPED 优先于 RPE、设备正常值、换站和奖励动画。暂停期间新报症状仍应升级处理。

计划至少包含：计划ID、版本、康复阶段、交付场景、有效期、来源状态、允许的活动及姿势、各阶段时长、可调整范围、所需监测、量表定义、停止规则、复核要求。训练使用计划快照；更新版计划不能在一局中途静默改变负荷。

第一轮实现计划校验和合成计划适配，不伪造医生账户或可信签名。生产计划的获取与真实性校验应由宿主/后端提供。缺失、过期、撤销、单位错误或规则冲突时均不使用通用默认值强行开训。

## 7. 可穿戴设备：默认可选，能力明确

### 7.1 接入层次

1. **手机独立模式（默认）**：执行明确允许无实时生理设备的计划，依靠患者自评、症状输入和实际动作识别。不能从姿态、步频或点击次数推导心率、血氧或临床安全。
2. **实时心率扩展**：优先完善现有标准心率服务适配。H5、微信原生蓝牙和厂商 SDK 各自实现适配器，向上提供同一事件协议。
3. **其他测量扩展**：血压、血氧、心电等按设备能力分别接入。训练前一次血压读数不能当作持续监测；消费级设备指标不能直接替代临床检查。
4. **研究网关扩展**：保留已有 WebSocket 方向，但移到开发/研究配置中，不让患者输入服务器地址；后续增加来源认证、数据校验和断连处理。

现阶段没有具体品牌型号、协议和实物，因此交付为适配契约及合成验证，不宣称支持“所有华为手表”或“所有蓝牙手环”。是否可读取实时心率、采样频率和微信后台行为，必须逐型号实测。

### 7.2 样本契约

每条样本包括：指标类型、数值、单位、来源类别、设备会话ID、采样时间（如设备提供）、本机接收时间、质量/接触状态（如提供）和序号。没有的字段明确为空，不虚构质量分数。手动录入、模拟、实时、历史补传分别标记。

新鲜度使用本机单调时间判断接收超时；设备时钟用于追溯，不能让设备时钟漂移把旧数据判成新数据。拒绝乱序、非有限值、单位不匹配和已关闭连接的迟到数据；换源后不沿用旧的超限累计。

### 7.3 断连和降级

| 情况 | 软件动作 |
|---|---|
| 当前计划允许手机独立训练，设备从未连接 | 告知未实时监测，按该计划检查后开训 |
| 当前计划要求实时设备，设备未就绪或首条有效数据未到 | 阻止开训 |
| 原本使用实时监测，设备断连或数据超时 | 先暂停并明确原因；不能静默忽略 |
| 允许降级的计划，用户希望转手机模式 | 重新核查症状与自评，明确确认后切换；记录切换时间和原因 |
| 不允许降级或已发生安全停止 | 保持暂停或停止；正常读数到来不能自动恢复 |

数据更新频率、新鲜度时限、触发持续时间等由经过验证的设备能力与临床规则共同确定；合成测试使用显式测试参数，不把工程占位值写成医学结论。

## 8. 与小喜鹊的风格及模块对接

### 8.1 视觉

已从参考仓库 `src/App.vue` 和 `src/pages/index/v7.scss` 核实：

手机竖屏为默认布局，横屏为可选的训练视图；停止入口在两种布局及所有弹窗中可达。正文目标不小于18px，主要触控区不小于48px；这是项目可用性目标，不是指南规定。设置低动态模式，暂停时停止背景切换；远距离看手机时依靠简短语音和大字提示，避免要求患者边踏步边阅读长文。

不直接复制小喜鹊的吉祥物、Rive资源或整个组件。其仓库未提供顶层开源许可；先独立实现一致的设计语言。参考项目的摄像头骨架装饰也不能替代本项目实际的MediaPipe识别反馈。

### 8.2 接入边界

宿主负责用户身份、可信计划和复核入口；游戏负责本次计划执行、即时停止和结构化结果。后续新增 `yunyou-shanhe` 活动标识，不强行映射为功率车或抗阻运动。

建议协议包含 `schemaVersion`、`sessionId`、`planId`、`planVersion`、模式与能力、各阶段时长、自评量表及回答、症状/停止事件、设备来源与质量摘要、结束原因。原始视频不进入协议。

H5嵌入态使用“返回今日计划”，避免重复底部导航。返回前先结束或暂停训练；结果只有得到宿主/服务端确认后才显示“已同步”。回传失败显示待同步，按会话ID幂等重试，不重复发奖。

微信 web-view 的消息机制不能作为可靠的实时急停总线。实时停止必须在训练运行端本地完成。微信原生与H5之间的蓝牙/摄像头数据通路需单独验证；不能因为网页在Chrome可用就宣称微信iOS可用。微信官方web-view页本轮抓取失败，接入阶段应再次核对官方文档和真机。

URL仅放允许公开的界面配置，患者身份、诊断、处方和访问令牌不得放入可分享链接。Web宿主采用明确来源校验；原生宿主走对应适配器，不能信任任意页面发来的“医生已批准”消息。
